# 2.8.0 使用说明

## 容量

- 16MB：电子书、词库、学习进度等共享约 12.6MB；电子书单次最大 8MB，单个词库最大 2MB / 20,000 词。
- 4MB：保留原来的 640KB 内容分区；电子书及词库单次最大 256KB，每库最多 5,000 词。
- 实际上传上限还受剩余空间限制。更换文件时临时文件与原文件同时占用空间，失败会保留原文件。
- 网页顶部显示实际 Flash 容量和内容存储的剩余 / 总空间。
- 默认仍是安全的 4MB 分区。同一份 OTA 固件兼容两种容量，不会把 4MB 的板子自动改成 16MB 分区。

## 你现在的 16MB 板子怎么扩容

只做网页 OTA 不会改动分区，16MB 板子仍可能只用到原来的 640KB。
要使用全部空间，先做一次串口扩容：

1. 解压文件包。保持电池供电，CH340 以 3.3V 串口电平连接 TX/RX/GND，收发交叉。
2. 按住 SW6（GPIO0 / BOOT），按一下 SW1（EN 复位），再松开 SW6。关闭串口监视器。
3. 在解压后的固件目录打开 PowerShell，执行下面命令，将 COM5 改成实际端口：

```powershell
python .\flash_release.py --port COM5
```

4. 脚本识别真实 4MB / 16MB 容量，先备份整个 Flash，再检查旧分区是否匹配。
   默认只更新引导程序、分区表、OTA 启动信息和应用程序，不写入旧词库、进度和设置所在分区。
5. 完成后不要按 BOOT，复位或重新上电。在网页顶部确认显示 16MB 和约 12.6MB 内容总空间。
   保留备份，直到确认电子书、词库和学习进度正常。

这个保留数据的升级脚本仅支持原 FortunePager 分区布局。
不支持的分区会停止，不会尝试强行覆盖。扩容后的 LittleFS 会在挂载时自动增长。
如果挂载失败，不会自动格式化，请保留串口日志和备份。

## 新板子或主动清空全部内容

只有需要重新写入预装词库、清空保存内容时，才使用：

```powershell
python .\flash_release.py --port COM5 --fresh
```

此模式也先备份，但会写入完整固件并替换电子书、学习进度和设置。
其他烧录工具使用对应容量的 `*_4MB_full.bin` 或 `*_16MB_full.bin`，起始地址 `0x0`。
绝不能把 16MB 完整包写进 4MB 芯片。

## 以后网页更新

连接热点 `FortunePager`，密码 `12345678`。
在 `http://192.168.4.1/update` 上传 `FortunePager_v2.8.0_ota.bin`。
更新登录是 `admin` / `12345678`。两种容量都使用这同一份 OTA 文件，内容和分区保持不变。
不要在 OTA 页面上传完整固件、分区表或文件系统镜像。

网页的“内容”中支持 TXT / Markdown / DOCX 电子书，以及 UTF-8 TSV 词库。
词库每行为“单词 + TAB + 释义”，单行最多 256 字节。
替换某个词库会清空该库学习进度，另一个词库不受影响。
如果新书没有足够的临时空间，可以先在网页删除旧书再上传。

屏幕方向与按键保持：SW4 NEXT、SW8 PREV、SW5 OK、SW2 BACK。

网页完整操作见仓库 `docs/WEB_GUIDE.md`，本体按键和功能说明见 `docs/DEVICE_GUIDE.md`。
